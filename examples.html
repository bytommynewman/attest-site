Examples

Three documents, start to finish.

The companies and people are fictional. The records are built with the app's own hashing and export code, so each file below verifies exactly as a real export does.

Now try to change the record.

Edit any note below. Your browser recomputes every hash, using the same formula as the app and the script.

    What this does and doesn't prove: someone able to rewrite the app's storage could recompute every hash after their change. So keep the newest hash from each export outside Confluence. A rewrite can't match it.

    Check a file yourself.

    The script needs only Node.js, and exits with an error if an entry was changed or is missing. It can't see the newest entries being removed, unless you compare a hash you kept. The sample output here is abridged.

    Download verify-audit.mjsReal export from our test site
    $ node verify-audit.mjs sample-audit-export.csv
OK    4358156: 2 entries, newest hash a33fc306…
OK    space:AQ: 1 entry, newest hash fab351cf…

3 entries verified across 2 chains.

$ # the same file with one word changed
FAIL  4358156: entry 2 has been altered
