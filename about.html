About Attest

An approval is a fact about one version.

Attest is a Confluence Cloud app for controlled-document approvals. It keeps each approval attached to the exact version that was signed, and ends it the moment that version changes or its review date passes.

What we believe

Most approval tools record that someone clicked approve. The record that matters says what they approved, and tells you the moment that stops being true.

A quality manual, a procedure or a policy is approved as a particular text, on a particular day, by particular people. Once the text changes, the approval describes something that no longer exists. If the record doesn't notice, the people relying on it won't either, until an auditor does.

So Attest treats the approval and the version as one thing. Signing records the page version and a fingerprint of its content. Publishing a new version resets the approval and writes who did it to the audit trail. Passing the review date resets it too. The record is only ever as current as the document it describes, and it says so.

Principles

Four things you can check, not take on trust.

Each one is a behaviour of the app, with the page where it's shown.

  1. 01

    The record must be checkable without trusting us.

    Every audit entry carries its sequence number, the previous entry's hash and its own. The export can be verified by a short script that shares no code with the app, using the formula published on the Product page. The check doesn't need the app, or us, to run.

  2. 02

    Nothing leaves Atlassian's platform.

    Attest runs on Atlassian Forge with no servers and no database of its own. Its manifest declares no outside network permissions, no remote services and no web triggers, and its code contains no analytics, tracking or advertising components. The Security page lists every permission it asks for and why.

  3. 03

    The record says when it can't be relied on.

    If the edit lock didn't apply, the panel says so. If the content no longer matches what was signed, the record says so. If the record can't load, it tells the reader not to rely on it. An entry altered to erase a closed account is marked redacted, counted separately and never counted as verified.

  4. 04

    We publish the limits, including what we haven't tested.

    The Security page lists what has run on a live site, what is covered only by unit tests and what hasn't been tried at all. A buyer of a document-control product is entitled to know where it stops before installing it. For the same reason we make no compliance claim a vendor can't make: Attest isn't 21 CFR Part 11 compliant or ISO 13485 certified, and no software vendor can deliver either. The accurate claim is approval records you can hand to an auditor.

How it's built

Small on purpose.

One module decides which state changes are legal, and the panel and the server both use the same rules for who may make them. The audit code only adds entries, with one automatic exception: removing a closed account.
